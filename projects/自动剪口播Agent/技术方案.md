# 自动剪口播 Agent

## 项目概述

把别人实现过的一套自动剪口播方案，整理归档并考虑本地落地。

## 核心问题

| 问题 | 描述 | 现有工具痛点 |
|------|------|-------------|
| 重复说 | 录视频时重复开头、话说一半停下重说 | 剪映智能剪口播只靠波形，无法识别语义重复 |
| 字幕质量差 | 专业词汇被ASR识别错误（Claude Code→正特，skills→excuse） | 云端ASR没有领域知识 |
| 语气词边界 | 删语气词时间戳会截断前字尾音，造成"吞字" | 直接按语气词时间戳删除，声音不自然 |

## 技术方案

### 三模型分工

```
云端ASR（字级时间戳）
    ↓
FunASR（口误识别：<STU>结巴、<FIL>语气词）
    ↓
Whisper large-v3（字幕底稿生成）
    ↓
Claude（语义审核 + 8条规则）
```

### 模型职责

| 模型 | 作用 | 特点 |
|------|------|------|
| 云端ASR | 音频→文字，字级时间戳 | 精确到每个汉字的起止时间 |
| FunASR | 口误识别 | 阿里达摩院开源，2GB，打标签<STU>/<FIL> |
| Whisper large-v3 | 字幕生成 | OpenAI开源，3GB，中英文混读断句好 |
| Claude | 语义审核 | 读可读文本，按8条规则审查 |

### 8条审核规则

1. 相邻两句话开头≥5字相同 → 删前面保留后面（重说）
2. 话说一半就停 → 整句删（残句）
3. "那个那个"、"就是就是" → 删前面保留最后一个
4. 句内重复（如"所以小所以"）→ 删前面半句
5. 语气词位于句中 → 删
6. 语气词位于句首/句尾 → 保留（承上启下）
7. [待补充]
8. [待补充]

### 关键逻辑：先分句再比对

**错误做法**（逐字扫描）：
```
原始："好，我们接下来开始做一个剪辑Agent.....嗯.....好，我们接下来开始做一个剪辑Agent，首先我们要打开Claude Code."
逐字扫描结果：删除了重复的字符串本身
留下："....嗯.....,首先我们要打开Claude Code."  ← 残句，听起来莫名其妙
```

**正确做法**（先分句再比对）：
```
步骤1：按静音停顿切成独立句子
  句子1："好，我们接下来开始做一个剪辑Agent"（说了一半停了）
  句子2：（一个停顿）
  句子3："好，我们接下来开始做一个剪辑Agent，首先我们要打开Claude Code"（完整）

步骤2：比对句子开头
  句子1 vs 句子3 → 开头完全相同，超过5字 → 判定为重说

步骤3：整句删除
  删除：句子1 + 句子2（停顿）

最终留下："好，我们接下来开始做一个剪辑Agent，首先我们要打开Claude Code。"
```

### 语气词边界处理

**问题**：直接按语气词时间戳删除，会截断前字的尾音，造成"吞字"。

**解决方案**：
- 删除区间 = 前一个字的**结束时间** 到 后一个字的**开始时间**
- 这样语气词对应的气流声被抹掉，但前后字完整

## 最佳实践

1. **专业模型做专业的事** — 不要让通用大模型包揽语音转写，专业语音模型又快又准
2. **词典持续维护** — 频道常出现的专业词汇、人名、工具名加入词典.txt，在两个地方生效：ASR热词 + 字幕校对参考
3. **语气词不要全删** — 适量"嗯""好"承上启下，全删会显得机械
4. **用好"自更新"机制** — 把修正偏好告诉AI，写入用户习惯目录，下次自动应用

## 所需工具

- 云端ASR（火山引擎或其他）
- FunASR（阿里达摩院开源，需下载）
- Whisper large-v3（OpenAI开源，需下载）
- Claude API（字幕审核）
- FFmpeg（精准切割）
